# 启动与使用

## 安装与运行

后端使用 uv 和 Python 3.12，前端使用 Node.js 22.12 或以上版本及 pnpm 11.4.0。依赖版本保存在 `backend/uv.lock` 和 `frontend/pnpm-lock.yaml`。当前开发环境使用 Python 3.12.13 和 Node.js 26.0.0。

在项目根目录执行：

```sh
cp .env.example .env
uv sync --project backend --locked
pnpm --dir frontend install --frozen-lockfile
```

已有 `.env` 时直接编辑，保留自己的配置。后端从根目录 `.env` 读取启动配置；环境变量优先于文件。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `ZHEN_WORKSPACE_ROOT` | `workspace` | 所有会话共用的工具工作目录 |
| `ZHEN_DATA_DIR` | `.local` | 数据库、密钥和运行设置 |
| `ZHEN_FRONTEND_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | 允许访问后端的页面来源，逗号分隔 |

路径可为绝对路径，相对路径以项目根目录为基准。默认目录会自动创建；工作目录不能位于私有数据目录内。改变配置后重启后端，新任务使用新的工作目录，旧记录保留原操作内容。

在两个终端分别运行：

```sh
uv run --project backend --locked uvicorn zhenagent.api:app --host 127.0.0.1 --port 8000
```

```sh
pnpm --dir frontend dev
```

打开 [工作台](http://127.0.0.1:5173)。后端必须保持单进程运行，不添加 `--workers` 或 `--reload`，避免重复执行任务。修改后端代码后手动重启。

前端默认访问 `http://127.0.0.1:8000`。更改后端端口时，复制 `frontend/.env.example` 为 `frontend/.env`，修改 `VITE_API_BASE_URL` 并重启前端；更改前端端口时同时更新后端允许的页面来源。首版面向 localhost，不提供远程访问或账号系统。

## 模型配置与会话

在“模型与运行设置”中填写服务地址、API key 和模型列表。默认 DeepSeek 地址为 `https://api.deepseek.com`，模型 ID 为 `deepseek-flash`；后端在地址末尾添加 `/responses`。兼容服务若要求 `/v1` 前缀，应把它写入服务地址，具体以服务文档为准。[DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)给出该服务的参数与限制。

每个模型可配置显示名称、思考强度和输出 token 上限。默认思考强度为 `high`；思考 token 计入输出预算。其他服务必须支持 Responses 流式响应、function 工具调用及配置中选择的参数。

密钥以明文保存在本机 `secrets.json`，文件权限为 `0600`，所在数据目录权限为 `0700`。保存后只显示“密钥已设置”，不回显原值；编辑时密钥留空会保留原密钥。密钥不会写入浏览器本地存储。不要把数据目录提交到 Git，尤其是自定义 `ZHEN_DATA_DIR` 时。

新建会话时选择服务和模型，之后不能切换，需要切换时另建会话。修改服务参数对随后启动的任务生效；正在执行的任务保留启动时配置。被已有会话引用的服务或模型不能移除。

发送消息后任务在后端执行。全局只运行一个任务，其他会话仍可查看历史。界面显示正文、各轮工具结果、失败尝试及调用次数。“思考过程”默认折叠，展开后显示模型服务实际返回的推理文本，生成过程中也会更新。关闭思考或服务未返回可显示的文本时，不显示该区域。

新请求按每次模型尝试保存推理文本，流中断时保留已有文本，并标记该次尝试中断；失败尝试不加入下一次模型上下文。旧版本已保存的推理内容在“历史思考记录”中按任务汇总显示。原始推理项仍完整保留、回传模型，展示功能不会额外调用模型。

## 工具与任务控制

列目录、读取 UTF-8 文件和字面搜索自动执行。搜索默认跳过 `.git`、`node_modules`、`.venv` 和 `__pycache__`；最多扫描 5000 个文件、返回 100 条匹配。文件工具检查解析后的真实路径，拒绝越过工作目录或访问 agent 私有数据目录。

写入与编辑等待批准：新建文件展示完整内容、行号和“新建文件”标记；修改已有文件展示增删行及数量。空文件明确标注，缺少末尾换行的内容也有提示。批准后核对原文件是否变化，变化则取消此次修改并向模型报告。编辑要求原文本在文件中唯一匹配。命令展示完整命令和工作目录，每次都需要批准，在本机 `/bin/sh` 中执行。文件工具的路径限制不约束已批准的命令。

拒绝任何审批会结束本次任务。点击“停止任务”会取消模型请求、失效待审批操作，并终止正在执行命令的进程组；已完成的修改与外部操作不会回滚。命令若主动脱离进程组，其后续行为不受进程组终止约束。

刷新或关闭页面后任务继续运行，重新打开可查看已有进度。等待审批的任务会保持等待，直到批准、拒绝或停止。后端异常退出后，下一次启动将未完成任务标记为中断，不自动恢复执行；正常退出会先停止活动任务。

## 上限与错误

“运行上限”页可调整后续任务的上限。默认每项任务最多 20 次模型请求，单条命令最多 120 秒，模型请求最多 180 秒。命令输出最多 1 MiB，模型响应最多 4 MiB，文件读取与写入最多 256 KiB，送入模型的工具结果最多 32 KiB；截取结果注明截取，界面保留受输出上限约束的完整工具结果。

网络错误、超时、HTTP 408、429 和服务端错误最多额外重试两次，默认等待 1 秒、2 秒，等待最长 30 秒。重试占用模型请求预算；认证和参数错误直接结束。失败尝试保留在界面，不进入下一次上下文。只有完整模型响应中的工具才会执行，重试不会重新执行已完成工具。

工具报错和命令非零退出会交回模型，让它在剩余预算内处理。停止、拒绝审批或达到调用预算会结束任务。首版没有上下文自动压缩，长会话被模型服务拒绝时可以另建会话。

## 构建与检查

```sh
pnpm --dir frontend build
uv run --project backend --locked python -m compileall -q backend/src
```

前端构建包含 TypeScript 类型检查，生成的 `frontend/dist` 可以单独托管。本机预览可运行 `pnpm --dir frontend preview`，后端仍须独立启动。调整页面地址后需要重新配置后端允许的来源。

本轮不提供或运行测试用例、假模型服务、功能测试和真实服务联调；这些验证由用户负责。消融实验也尚未执行，见 [实验计划](../experiments/2026-10-10-工具消融计划.md)。
