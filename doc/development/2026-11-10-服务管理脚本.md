# 服务管理脚本记录

- 日期：2026-11-10
- 状态：已完成

## 目标与关联文档

提供后端与前端服务的一键启动、停止、重启与状态检查脚本，解决此前需要手动分窗口启动且停止繁琐的问题。

- 需求文档：[服务管理脚本需求](../requirements/2026-11-10-服务管理脚本.md)
- 设计方案：[服务管理脚本设计](../design/2026-11-10-服务管理脚本.md)
- 使用说明：[启动与使用](usage.md)

## 实际改动

1. 新增 `scripts/common.sh`：定义路径定位、PID/日志目录、环境依赖检查（`uv`、`pnpm`）、局域网 IP 自动获取、递归子进程采集、优雅终结与就绪轮询逻辑。
2. 新增 `scripts/start.sh`：以 `0.0.0.0` 绑定启动后端与前端，记录 PID，在终端和 `.local/logs/` 头部展示本地与局域网访问地址，完成就绪探测。
3. 新增 `scripts/stop.sh`：根据 PID 递归停止进程树（覆盖 `uvicorn` 与 `vite` 等子进程），清理 PID 记录。
4. 新增 `scripts/restart.sh`：先执行停止再执行启动，支持指定目标。
5. 新增 `scripts/status.sh`：检查前后端服务存活状态、PID、监听端口、本地与局域网访问地址。
6. 在根目录新增 `start.sh`、`stop.sh`、`restart.sh`、`status.sh` 转发入口，赋予可执行权限。
7. 后端放宽局域网访问：在 `backend/src/zhenagent/api.py` 增加私有 IP（RFC 1918）Origin 校验，`TrustedHostMiddleware` 放宽主机限制，防止局域网设备请求被拒。
8. 前端自适应后端地址：在 `frontend/src/api.ts` 支持依据当前窗口 host 动态生成 API 接口地址，并在 `frontend/package.json` 将 dev/preview 统一监听 `0.0.0.0`。
9. 更新 `README.md` 和 `doc/development/usage.md`，增加脚本使用方法；更新相关文档索引。

## 验证

1. 脚本执行权限与语法检查：
   - 运行 `bash -n scripts/*.sh *.sh`，语法检查全部通过。
2. 参数与状态逻辑验证：
   - 运行 `./status.sh`：正确显示前后端未运行状态与对应日志文件路径。
   - 运行 `./stop.sh`：未运行时输出友好提示，清理陈旧记录并正常退出。
   - 运行 `./stop.sh unknown`：输出参数使用说明并以状态码 1 退出。
3. 构建与静态检查：
   - 运行 `pnpm --dir frontend build`：TypeScript 类型检查与前端打包通过。
   - 运行 `uv run --project backend --locked python -m compileall -q backend/src`：Python 字节码编译通过。
4. 功能测试与真实联调：按约定由用户自行在本机验证。
