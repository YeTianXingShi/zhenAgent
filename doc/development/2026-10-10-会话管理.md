# 会话名称与物理删除

- 日期：2026-10-10
- 状态：已完成

## 目标与关联文档

用户要求修改会话记录名称，以及物理删除会话记录。物理删除指删除数据库中的实际记录，不使用归档或软删除；不删除工作目录文件和服务配置，也不承诺磁盘级安全擦除。

## 实际改动

侧栏每个会话提供重命名和删除按钮，使用 Dialog 编辑名称及确认永久删除。名称去除首尾空白，必须含非空白字符，最多 100 字符。手动名称增加持久化标记，避免首次用户消息的自动命名覆盖它，包括手动命名为“新会话”的情况。

新增 `PUT /api/sessions/{id}` 与 `DELETE /api/sessions/{id}`。删除在一个事务中依次清除 items、events、tools、attempts、runs 和 sessions；失败时回滚。禁止删除正在执行、等待审批或仍在收尾的会话。删除与任务启动共用 agent 锁，任务启动在锁内再次确认会话存在，避免删除后继续创建任务。

删除当前会话后清除界面选择、消息输入与提交缓存；删除其他会话保留当前会话。服务密钥和配置保持原样。

参考本地 OpenCode `packages/core/src/session/projector.ts` 的 SessionV1.Event.Deleted 处理：它删除 SessionTable 行。本项目没有引入事件投影架构，直接使用 SQLite 事务显式删除关联记录。

## 方案与消融计划

基线为上述事务删除、启动互斥与手动名称标记方案。计划在隔离的临时数据库与相同会话数据下，逐项移除事务、启动互斥和名称标记，分别比较删除中断后的残留、启动与删除竞争、首次消息是否覆盖手动名称。每组只改变一项机制，记录数据完整性与错误。实验尚未执行，本轮不运行功能测试，由用户验证。

## 遗留问题

用户需验证空白和超长名称、首次发送后的名称保留、运行中删除拒绝、删除后刷新和关联记录清除。数据库事务删除不是磁盘安全擦除。已确认无活动任务后重启后端，启动完成，新接口和迁移已加载；未执行重命名或删除请求。
