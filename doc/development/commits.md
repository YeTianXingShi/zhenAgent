# 提交规范

采用 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/zh-hans/v1.0.0/)。类型标记使用英文小写，说明和正文使用中文；技术名称、路径、接口名以及规范要求的标记保留原文。

## 格式

```text
类型(可选范围): 中文说明

可选中文正文

可选脚注
```

类型后的冒号和空格使用半角字符。范围可以省略，也可以使用模块名或文档分类。首行说明实际变化，需要补充原因、影响或迁移方式时写正文。

## 类型

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat: 添加工具调用入口` |
| `fix` | 修复问题 | `fix: 修复会话恢复失败` |
| `docs` | 文档 | `docs: 补充开发规范` |
| `refactor` | 保持功能行为的重构 | `refactor: 调整消息处理结构` |
| `test` | 测试 | `test: 补充错误处理用例` |
| `perf` | 性能改动 | `perf: 减少重复读取` |
| `build` | 构建或依赖 | `build: 更新依赖版本` |
| `ci` | 持续集成 | `ci: 添加文档检查` |
| `chore` | 维护与项目配置 | `chore: 初始化项目文档与开发规范` |
| `style` | 不改变行为的格式调整 | `style: 统一缩进` |
| `revert` | 回退改动 | `revert: 回退配置调整` |

以上示例只说明格式，不代表项目已实现这些功能。一个提交围绕一个完整改动；不同目的的改动分别提交。

## 破坏性变更

在类型或范围后、冒号前添加 `!`，并说明影响与迁移方式：

```text
feat(会话)!: 调整会话加载接口

说明接口变化、受影响的调用方及迁移方式。
```

需要使用破坏性变更脚注时保留标准标记 `BREAKING CHANGE:`，其后的说明写中文。其他脚注如 `Refs: #编号` 按规范保留标记。

## Git 模板

仓库提供根目录 `.gitmessage`。首次初始化会配置本地模板，克隆到新环境后执行：

```sh
git config --local commit.template .gitmessage
```

随后使用 `git commit` 打开模板填写信息。使用 `git commit -m 'docs: 补充开发规范'` 时也应遵守相同规则。

模板只提供提示，提交格式目前通过人工核对执行；后续需要自动检查时再配置 hook 或检查工具。
