# UI 组件接入消融计划

- 日期：2026-10-10
- 状态：计划

## 问题与假设

现成 UI 组件是否减少维护代码，同时保留聊天工作台所需的视觉控制？假设组件库能减少基础控件的手写代码，但样式配置和源码维护可能抵消部分收益。

## 基线与消融项

基线为当前手写 React 控件和 CSS。固定同一份设置表单、按钮与弹窗需求：A 组仅把基础控件替换为 shadcn/ui；B 组仅替换为 Mantine；各组保持业务状态、API、文本和布局要求一致。选定候选后，再逐项移除自定义主题和组件封装，观察它们的独立作用，不同时改变多个机制。

## 实验条件

执行前记录基线 commit 和各依赖的锁定版本。使用相同 Node.js、pnpm、构建配置和界面数据；不调用真实模型。每个构建方案重复三次，记录产物体积及构建结果。运行效果由用户手动验证，本轮不执行功能测试。

## 指标与判断标准

比较需维护的控件与样式代码量、新增依赖数、构建产物 gzip 大小，以及满足相同布局要求所需的额外改动。用户评估表单操作、弹窗键盘行为和视觉一致性。代码量减少但维护改动或体积明显增加时，不能据此判定整体收益更高。

## 结果

尚未运行，无测量数据。

## 结论与限制

当前只有选型建议。后续结果仅适用于所选控件和锁定版本，不能直接推广到整个聊天区。
