# 0001：项目初始化与文档管理

- 日期：2026-10-10
- 状态：已接受

## 背景

项目计划使用 Python 和 Node.js 实现 agent，当前需要先建立文档留存和版本管理方式。首个功能及两种语言的职责尚未确定。

## 决策

- 本轮建立项目规则和基础配置，代码骨架留到首个功能设计。
- 使用标准的 `AGENTS.md` 作为规则入口，具体流程按需从 `doc` 加载。
- 文档按需求、调研、设计、决策、实验和开发记录分类；保存影响项目的聊天结论，修改历史由 Git 留存。
- 使用本地 `main` 和短期任务分支，在 GitHub 创建公开的 `YeTianXingShi/zhenAgent` 仓库。正式文档随代码公开，私人材料存放在 `.local`。
- 提交遵循 Conventional Commits，类型标记用英文，说明及正文用中文，技术名称保留原文。提供模板，暂不配置自动检查或 hook。
- 完整追踪 shuorenhua 安装目录。本项目使用 MIT 许可证，第三方文件保留原有许可证。

## 备选方案

- 本轮创建代码骨架：职责和首个功能尚未确定，用户选择先建立规则。
- 保存完整聊天：用户选择保存关键结论与正式文档，历史通过 Git 查看。
- 中文类型标记：用户选择保留标准英文类型，以便使用常见提交工具。
- 提交自动检查：用户选择先只写规范，后续需要时再添加。
- 私有远程仓库、只追踪 skill 运行文件：用户选择公开仓库并追踪完整安装目录。
- 保留 `agent.md`、扁平文档目录：用户选择标准入口和分类文档。

## 影响

克隆仓库后可以读取项目文档和同一份 shuorenhua skill。公开内容包含正式开发记录和上游 skill 的评测材料，需要区分本项目记录与上游结果。

本决策确定的是初始化管理方式；本轮没有待验证的 agent 机制，因此没有功能消融实验结果。后续功能方案遵循项目的消融实验要求。
