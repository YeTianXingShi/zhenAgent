# 服务管理脚本设计

- 日期：2026-11-10
- 状态：已确认

## 目标与约束

链接需求：[服务管理脚本需求](../requirements/2026-11-10-服务管理脚本.md)。

约束与条件：
1. 本地 macOS 与 Linux 环境下均可执行，使用 POSIX / standard bash 语法。
2. 后端与前端绑定 `0.0.0.0`，同时监听本地回环地址（`127.0.0.1` / `localhost`）与局域网 IP。
3. 后端后端端口默认 8000，前端端口默认 5173。
4. 数据与运行临时文件保存在 `.local`（已被 Git 忽略），不污染工作区。
5. `uv` 和 `pnpm` 启动时会派生子进程（如 `uvicorn`、`node vite`），停止时必须完整终结整棵进程树，避免孤儿进程继续占用端口。
6. 支持局域网设备跨端访问：后端需放宽局域网私有 IP（RFC 1918）跨域与 Host 限制，前端在未配置 `VITE_API_BASE_URL` 时根据当前访问的主机名自动拼接后端接口地址。

## 方案

### 目录与文件布局

```text
zhenAgent/
├── scripts/
│   ├── common.sh     # 公共函数、环境检查、PID 与进程树管理、就绪检测
│   ├── start.sh      # 启动脚本
│   ├── stop.sh       # 停止脚本
│   ├── restart.sh    # 重启脚本
│   └── status.sh     # 状态检查脚本
├── start.sh          # 根目录快捷入口（转发至 scripts/start.sh）
├── stop.sh           # 根目录快捷入口（转发至 scripts/stop.sh）
├── restart.sh        # 根目录快捷入口（转发至 scripts/restart.sh）
└── status.sh         # 根目录快捷入口（转发至 scripts/status.sh）
```

运行时生成文件（在 `.local/` 目录下）：
- `.local/run/backend.pid`：后端进程 PID
- `.local/run/frontend.pid`：前端进程 PID
- `.local/logs/backend.log`：后端标准输出与错误日志
- `.local/logs/frontend.log`：前端标准输出与错误日志

### 模块职责与输入输出

1. `common.sh`：
   - 定位项目根目录，无论在何处调用均解析为绝对路径。
   - 自动获取局域网 IPv4 地址（支持 macOS `ipconfig` 遍历网卡、Linux `hostname -I`、Python UDP 路由及 `ifconfig`）。
   - 配置绑定主机 `0.0.0.0`，计算本地地址（`127.0.0.1`）与局域网访问地址。
   - 读取 `.env`，缺省时使用端口 8000 与 5173。
   - 依赖检查：`uv`、`pnpm`、前端依赖目录 `frontend/node_modules`。
   - 进程树管理：通过 `pgrep -P` 递归收集子孙进程 PID，先发送 `SIGTERM`，超时未退出（默认 10 秒）发送 `SIGKILL`。
   - 就绪轮询：使用本地地址探测后端健康接口（`/api/settings`）与前端地址，最多等待 15 秒，检测到服务提前崩溃则输出日志末尾内容并报错。
2. `start.sh [all|backend|frontend]`：
   - 默认启动前后端两项服务；支持单独启动。
   - 检查服务是否已在运行；检查端口是否冲突。
   - 将启动时间、绑定监听地址、本地访问地址和局域网访问地址写入对应日志文件头部。
   - 使用 `nohup` 脱离终端并在后台运行，记录 PID 至 `.local/run/`。
   - 轮询等待就绪后在终端输出服务本地与局域网访问地址、日志路径及操作指引。
3. `stop.sh [all|backend|frontend]`：
   - 默认停止前后端两项服务；支持单独停止。
   - 读取 PID 并终结父进程及其子孙进程，清理对应 PID 文件。
   - 检查端口占用是否已释放，未释放时输出辅助排查提示。
4. `restart.sh [all|backend|frontend]`：
   - 依次调用 `stop.sh` 与 `start.sh`，保证端口安全释放后重新启动。
5. `status.sh [all|backend|frontend]`：
   - 检查后端与前端进程运行状态、端口监听及 PID 文件一致性。

## 备选方案与取舍

1. **单文件全部合一 vs 拆分模块与入口**：
   - 备选：把所有逻辑写在一个 `manage.sh` 中，通过子命令（`manage.sh start`）执行。
   - 取舍：用户明确要求增加“启动、停止、重启三个脚本”，直接提供 `start.sh`、`stop.sh`、`restart.sh` 更直观，符合用户的使用预期。将核心逻辑抽入 `scripts/common.sh`，根目录提供快捷转发，兼顾了模块复用与操作便利。
2. **前台运行 vs 后台 Daemon 模式**：
   - 备选：启动脚本阻塞前台，同时输出前后端日志。
   - 取舍：前台同时跑两个进程难以单独重启某一个，且关闭终端会导致服务中断，无法满足配套的“停止”与“重启”脚本需求。采用后台运行记录 PID，日志写入 `.local/logs/`，并提供状态查看与 tail 命令指引。
3. **单 PID kill vs 递归进程树终止**：
   - 备选：仅对记录的 PID 执行 `kill $pid`。
   - 取舍：`uv run` 与 `pnpm dev` 都会启动子进程，仅 kill 父进程常导致子进程被 1 号进程接管成为孤儿进程，继续占用 8000/5173 端口。必须递归采集子进程并一并终止。
