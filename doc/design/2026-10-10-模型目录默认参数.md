# 模型目录与默认参数

- 日期：2026-10-10
- 状态：已确认

用户要求默认从 Models.dev 获取模型参数。后端通过 HTTP GET 读取 `https://models.dev/api.json`，独立模块负责下载、解析、缓存与参数解析。前端只访问 Python API。

## 数据与覆盖

服务配置增加可空的 `catalog_provider_id`，模型保存 ID、名称覆盖和可空的输出上限、思考强度覆盖。覆盖值与目录元数据分别返回，界面不会把解析后的默认值重新保存为覆盖。

模型名称按手动名称 → 目录名称 → ID 取值。输出 token 上限按手动值 → 目录 `limit.output` → 省略请求字段取值；不再应用固定 8192 或固定 131072 上限。思考档位来自目录，用户未选时省略 `reasoning`。温度无数值默认项，因此不发送。目录上下文和输入上限作信息展示，不实现上下文压缩或 token 计数。

任务启动时解析并冻结参数。之后更新目录或修改设置只影响新任务。手动服务可不关联目录；目录缺少模型或字段时明确提示，并交给模型服务处理未指定参数。

## 缓存与接口

缓存为数据目录的 `models-dev.json`，包含来源、获取时间和原始 JSON，原子替换且权限为 0600。下载有超时及 32 MiB 大小限制。启动时优先读缓存，过期则更新；运行每小时更新。失败不替换已有缓存，界面显示错误和过期状态。没有缓存时仍启动本地服务，允许手动配置。

- `GET /api/model-catalog`：来源、时间、错误与服务列表。
- `GET /api/model-catalog/providers/{id}`：指定服务的模型信息。
- `POST /api/model-catalog/refresh`：更新公共目录，失败结果在状态字段中返回。

目录收录不能证明 Responses 兼容性，尤其不同协议的输出限制和推理控制可能不同。界面说明这一边界并提供覆盖字段。

## 升级

数据库仅增加目录关联列。首次升级按已有服务 ID 或唯一相同地址关联目录，保留已有模型、参数覆盖、密钥和会话；目录首次获取失败时延后关联。用户可通过“恢复目录默认”清空覆盖并保存。新安装不再注入固定服务和模型，而是在界面选择目录条目。

## 消融计划

尚未执行；按用户约定由用户手动验证，不编写或运行测试用例。基线为目录关联、缓存、可空覆盖和任务参数冻结全部启用。在相同目录数据、服务和模型下逐项比较：

| 移除或替换的机制 | 相同条件 | 观察指标 |
| --- | --- | --- |
| 将目录默认替换为旧固定值 | 同一模型、空覆盖 | 输出预算是否跟随目录变化 |
| 移除缓存 | 目录服务不可达、已有历史配置 | 重启后能否取得默认参数 |
| 保存解析值而非空覆盖 | 更新目录输出上限 | 新任务是否继续使用过时值 |
| 移除任务参数冻结 | 任务运行中更新目录 | 同一任务是否混用不同预算 |
