# 上下文与温度设置

- 日期：2026-10-10
- 状态：已确认

模型配置增加可空的 `context_tokens` 和 `temperature`。上下文上限为正整数，手动值优先，留空跟随 Models.dev 的 `limit.context`，未提供时不设置本地上限。温度范围 0–2，允许 0；留空省略请求字段，不补固定默认值。Models.dev 的温度字段表示支持能力，不是数值默认值。运行中的任务冻结启动时参数，更新只影响新任务。

## 实际用量与停止条件

后端保存响应的完整 `usage`，界面读取 `input_tokens`、`output_tokens`、`total_tokens`、`input_tokens_details.cached_tokens` 和 `output_tokens_details.reasoning_tokens`。缓存命中包含在输入内，推理包含在输出内，均不重复计数。优先使用返回的总量；总量缺失且输入与输出都已返回时，相加这两个实际值；其他情况显示未提供，不估算。这些字段的含义见 [DeepSeek Responses 文档](https://api-docs.deepseek.com/zh-cn/api/create-response/)。同一文档规定温度范围为 0–2，思考模式下温度不生效。

上下文判断使用最近一次已加入会话的完整响应的实际总量，不累计多轮请求用量。发起下一轮前检查历史统计；完整响应写入会话后再次检查，达到上限即结束任务，保留生成内容，取消尚未执行的工具并补齐取消结果。新建任务也检查最近的会话统计，可通过新建会话或调高上限继续。服务返回失败或不完整响应时仍保存可用统计，但不把失败输出加入会话或作为后续上下文依据。

模型请求返回前无法获得新消息、工具结果的精确 token 数，因此这不是发送前的精确长度校验。服务未返回统计时无法执行本地上限判断；不回退到本地估算，也不沿用更旧响应的统计替代缺失值。服务端仍可能先拒绝超长请求。首版不压缩、不删除历史，也不发送不存在的 Responses 上下文长度参数。

每次尝试保存当时的 `context_limit`，历史展示不受后续设置影响。旧记录该字段为空，不补造历史上限。SQLite 仅追加可空列，模型配置继续保存在原 JSON 字段中，缺少新增字段时按空覆盖处理。

## 消融计划

尚未执行；按用户约定不编写或运行测试用例，由用户手动验证。基线为实际 usage、可空覆盖、任务冻结及按尝试保存上限均启用。各项比较使用同一服务、模型与对话内容，逐项替换机制：

| 移除或替换的机制 | 条件 | 观察内容 |
| --- | --- | --- |
| 移除上下文停止判断 | 完整响应实际用量达到设置上限 | 是否继续请求模型或执行后续工具 |
| 将单次总量替换成多轮累计值 | 多轮反复携带相同历史 | 是否因重复累计提前停止 |
| 将缓存命中再加到输入中 | 服务返回缓存命中统计 | 是否重复计数并提前停止 |
| 将空覆盖替换为保存解析值 | 更新 Models.dev 上限 | 新任务是否继续采用过期上限 |
| 移除参数冻结和历史上限快照 | 任务中途或完成后更改设置 | 任务及历史是否混用不同设置 |

不把计划写成验证结果。相关实现与检查见 [开发记录](../development/2026-10-10-上下文与温度.md)。
